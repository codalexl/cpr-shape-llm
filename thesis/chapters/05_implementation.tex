\chapter{Implementation}
\label{ch:impl}

The training loop is ShapeLLM's, reused with permission and unmodified in
its rollout structure \cite{garciasegura2025}; the environment, the agent-2
learning rules, the evaluation battery and the analysis are this project's.
This chapter names what an examiner would open, and what is pinned by tests.

Agent 2's learning rule is selected entirely by configuration keys:
\texttt{trial\_batched} for the control, \texttt{is\_shaper} for the trial
objective, \texttt{transmit\_info} for the trial-memory prompt, and
\texttt{cross\_episode\_credit} for the estimator.
Two arms therefore differ in exactly the keys their contrast names, which
\texttt{tests/test\_cpr\_dial\_configs.py} asserts key by key.

\section{Entry points}
\label{sec:impl-entry}

\texttt{finetuning\_cpr.py} trains two agents; \texttt{finetuning\_cpr\_fixed.py}
trains one against a scripted or frozen partner, which covers the gates, the
probe and the frozen battery.
\texttt{scripts/make\_dial\_configs.py} derives every configuration from one
base file so that arms differ only where intended, and refuses to write a
file that \texttt{check\_dial\_config} rejects.
\texttt{scripts/schedule\_dial.py} runs a phase one process per GPU, skips
runs whose records exist, and orders jobs so that a phase can be restarted
after an interruption.
Each run serialises per-round records, the epoch-1 openings used for the
seed check, the live advantages and the training statistics.

\section{Analysis}
\label{sec:impl-analysis}

Every number in Chapters~\ref{ch:env} and~\ref{ch:results} is produced by a
script from the records or the solver.
\texttt{cpr\_dial.py} prints the design report and the invariants.
\texttt{scripts/evaluate\_dial.py} holds the estimators: the window
summaries, the four probe rates and the policy class, the gate readouts and
the within-trial channel measure, and it applies the decision rules.
\texttt{scripts/dial\_results\_tables.py} and
\texttt{scripts/dial\_figures.py} compose those estimators into the tables
and figures of Chapter~\ref{ch:results}, so no quantity is computed in two
places.
\texttt{scripts/dial\_credit\_replay.py} re-credits recorded trials under
alternative estimators, and \texttt{scripts/dial\_learnability.py} and
\texttt{scripts/dial\_shaping\_window.py} produce the pre-training analyses
of Chapter~\ref{ch:design}.

\section{Tests}
\label{sec:impl-tests}

The suite runs before every launch; 161 tests pass at the commit this report
was built from.
\texttt{tests/test\_cpr\_dial.py} pins the environment against the live
dynamics and the invariants I2 and I3 at both design points.
\texttt{tests/test\_trial\_batching.py} and
\texttt{tests/test\_cross\_episode\_credit.py} pin the control and the
estimator as pure functions and then through the agent, including that the
split-credit baseline comes from previous trials and not from the current
one.
\texttt{tests/test\_evaluate\_dial.py} checks every estimator against
records simulated from policies of known value, the gate logic, the channel
measure and the decision rules, including that a missing seed never helps a
claim.
\texttt{tests/test\_cpr\_dial\_configs.py} is the configuration lock, and
\texttt{tests/test\_schedule\_dial.py} checks that the folders the scheduler
writes are the folders the evaluator reads.
